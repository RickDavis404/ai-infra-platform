# Valkey — Langfuse BullMQ queue + cache

Valkey is Langfuse's **BullMQ job queue** plus ephemeral cache. It is **not** an
authoritative store: BullMQ re-enqueues in-flight jobs on reconnect, so a Valkey
restart costs at most some job re-processing, not data loss. That guarantee is why
the **primary runs without persistence** (spec §12.4).

This is the **valkey-io project chart** — the correct non-Bitnami replacement for
the old Bitnami valkey subchart. It declares no dependencies and has no Bitnami
direct/transitive footprint. At `0.10.0` the chart's native `appVersion` is `9.1.0`,
so the prior manual `9.1.0-*` image override is unnecessary. The chart is driven by
a small maintainer team (bus-factor flagged), though cadence is solid; re-test on
any version bump.

Render with the `--enable-helm` flag:

```bash
kustomize build --enable-helm kubernetes/langfuse-data/valkey | kubectl apply -f -
```

## HA topology — 1 primary + 2 replicas

`replica.enabled: true`, `replica.replicas: 2` → **1 primary + 2 replicas (3 pods)**.
The deployment survives one pod loss with a replica still present after failover.
`replica.minReplicasToWrite: 1` gives a **soft write-quorum** (the primary blocks
writes if fewer healthy replicas are in sync). Required pod anti-affinity on
`kubernetes.io/hostname` spreads the three pods across the three nodes, and the PDB
keeps `minAvailable: 2` (primary + one replica) through voluntary disruptions
(spec §6.2).

## Eviction policy — never drop queue jobs

`valkeyConfig` sets `maxmemory-policy noeviction` with `maxmemory 256mb`. Queue jobs
must never be silently dropped, so under memory pressure the server **blocks** rather
than evicting. The pod memory **limit is 320Mi** — deliberate headroom above the
256mb cap.

## Persistence — primary off, replicas warm

- **Primary:** `dataStorage.enabled: false`. No PVC; RTO is pod restart time. This is
  justified by the BullMQ re-enqueue guarantee above.
- **Replicas:** the valkey-io chart's replicated mode **requires** a per-replica PVC,
  so each replica gets the spec's documented **optional ~1Gi `local-path` PVC**. This
  enables warm failover (a replica can be promoted without a full re-enqueue) at
  negligible cost and keeps the chart render valid. It is the spec §12.4 "optional 1Gi
  PVC for warm failover" path, made concrete.

## Auth — deterministic password from the shared secret

The chart reads each ACL user's password from `auth.usersExistingSecret` at the
per-user `passwordKey`. We pin:

- `auth.usersExistingSecret: langfuse-shared-passwords`
- `auth.aclUsers.default.passwordKey: redis-password`

so the password matches Langfuse's `redis.auth.existingSecret` /
`existingSecretPasswordKey` (`redis-password`) from §12.1. The Secret itself is
generated by the fnox+age secrets pipeline (cross-namespace mirror via the shared
`.dec`); it is **never** authored here.

> **Chart-knob note (vs. the §12.4 excerpt).** The spec excerpt uses Bitnami-style
> names (`auth.usersExistingSecretKey`, top-level `podAntiAffinity`, `pdb`). The
> pinned valkey-io chart's real schema is different and is what `values.yaml` uses:
> the secret key is the per-user `aclUsers.default.passwordKey`, spreading is raw
> `affinity.podAntiAffinity`, and the budget is `podDisruptionBudget`. The intent
> (existing-secret key `redis-password`, required hostname anti-affinity, PDB
> `minAvailable: 2`) is preserved exactly.

## Service name — for Langfuse `redis.host`

With `replica.enabled: true` the chart at `0.10.0` exposes the **primary Service as
`langfuse-valkey`** (plus `-read`, `-headless`, and `-metrics` Services). Langfuse's
`redis.host` (§12.1) must therefore target:

```
langfuse-valkey.langfuse-data.svc.cluster.local
```

> The §12.1 excerpt's placeholder host `langfuse-valkey-primary...` reflects a
> different chart's naming; the spec explicitly requires confirming the primary
> Service name against the pinned chart — for `0.10.0` it is `langfuse-valkey`.

## Metrics

`metrics.enabled: true` runs the Prometheus exporter sidecar; the `langfuse-valkey-metrics`
Service exposes it for scraping by the observability plane (`lgtm`).

## Out of scope / external access

No Ingress, no LoadBalancer, no externally-routed Service. All access is in-cluster
ClusterIP (`:6379`) or, for debugging, `kubectl port-forward` to `127.0.0.1`.
